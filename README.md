# Cleaning Go

Монорепозиторий MVP маркетплейса клининговых услуг: mobile-first Expo Router для
клиентов, клинеров и компаний; Next.js PWA с лендингом и защищённой админ-панелью;
Supabase PostgreSQL/Auth/Realtime/Storage.

## Что реализовано

- Роли `client`, `cleaner`, `company_owner`, `company_cleaner`, `admin`; публично нельзя создать `admin`.
- Email/пароль, телефон в профиле и готовность к Supabase Phone OTP после подключения SMS-провайдера.
- Каталог, выбор проверенной компании или свободного клинера, расчёт цены на сервере, заказы, назначения, история статусов, отзывы и споры.
- Рекомендация клинеров по городу, доступности, рейтингу и числу отзывов; закреплённая промокодом компания всегда имеет приоритет.
- Realtime-точка клинера только для участников активного заказа; точка удаляется в финальном статусе.
- Реферальный код, кошелёк, неизменяемый журнал и идемпотентное начисление после оплаченного завершённого заказа.
- Снимки процентов в каждом заказе, чтобы изменение настроек не меняло старую экономику.
- Кабинеты клинера и компании, сотрудники, лимиты, отчёты и внутренние уведомления.
- Админ-панель: метрики, верификации, заказы, люди, блокировки, услуги, цены, отзывы, споры и проценты.

## Быстрый запуск

1. Установите Node.js 20+, pnpm 10+, Supabase CLI и Expo Go.
2. Скопируйте `.env.example` в `.env` и заполните публичные ключи.
3. Выполните `pnpm install`.
4. Локальный backend: `supabase start && supabase db reset`.
5. Мобильное приложение: `pnpm dev:mobile`.
6. Админ-панель: `pnpm dev:admin`.

Админ-панель находится на `/admin`. Доступ требует одновременно роль `admin` в `profiles`
и точное совпадение email с `SEED_ADMIN_EMAIL`. Публичная регистрация не принимает эту роль.

Для email/phone OTP настройте провайдеры Authentication в Supabase. Реальные
карточные платежи намеренно не подключены. Архитектура описана в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Допущения MVP

- Наличные и тестовые заказы помечаются оплаченными, когда клиент подтверждает завершение. Карточный
  платёж остаётся `pending`, пока будущий адаптер провайдера не подтвердит оплату. Для реального онлайн-платежа нужны договор и секреты выбранного провайдера.
- AI-диалог для уточнения заказа и LLM-рекомендации не включаются без серверного ключа провайдера: текущая рекомендация намеренно объяснимая, на правилах, а не имитация AI.
- Геолокация MVP передаётся только при открытом приложении. Фоновое отслеживание не заявлено.
- Push, SMS, email и банковские выплаты остаются адаптерами для будущего провайдера.

## Безопасность

Не помещайте service-role, SMS, email или карты-ключи в публичные переменные.
Администратор создаётся доверенным seed/серверным процессом, а не регистрационной
формой. Перед production необходимо включить CAPTCHA, rate limits, MFA для админов,
резервное копирование и юридически согласованные политики хранения документов.
