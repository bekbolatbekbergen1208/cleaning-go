# Cleaning Go

Локальная версия маркетплейса клининга: Next.js PWA и Expo для клиентов, клинеров,
компаний и администратора. Облачный Supabase и его SDK удалены. Данные хранятся
в PostgreSQL через PGlite на диске компьютера; файлы и сессии тоже локальные.

## Запуск

Требуется Node.js 22+ и pnpm 10.14.0 (версия закреплена в packageManager).

```bash
pnpm install
node local/setup.mjs
node --env-file=.env.local local/create-admin.mjs
```

`setup` создаёт случайный серверный ключ и пароль локального администратора в
`.env.local`, конфигурации веб- и мобильного приложений. Email администратора по
умолчанию `admin@cleaning.local`; пароль — `SEED_ADMIN_PASSWORD` в корневом
`.env.local`. Не публикуйте этот файл. Повторный `setup` сохраняет ключ и пароль.
Создавайте/обновляйте администратора при остановленном API: база открывается одним процессом.

В двух отдельных терминалах из корня проекта:

```bash
node --env-file=.env.local local/server.mjs
```

```bash
pnpm --filter @cleaning-go/admin dev
```

Сайт: http://localhost:3000. Администратор: http://localhost:3000/admin/login.
Проверка API: http://127.0.0.1:54321/health.

Мобильное приложение:

```bash
pnpm --filter @cleaning-go/mobile start
```

Для физического телефона укажите IP компьютера вместо `127.0.0.1` в
`apps/mobile/.env.local`: `EXPO_PUBLIC_LOCAL_API_URL` и
`EXPO_PUBLIC_REGISTRATION_API_URL=http://IP:3000/api/register`.
Запускайте API с `LOCAL_API_HOST=0.0.0.0`. Для Expo Web с другого адреса добавьте
его точный origin в `LOCAL_ALLOWED_ORIGINS` корневого `.env.local` (через запятую).
Переменные сервера читаются при старте, публичные переменные — при сборке приложений.

## Где лежат данные

- `.local-data/db/` — PostgreSQL, пользователи, заказы, бонусы, отзывы, сессии.
- `.local-data/files/` — загруженные фотографии и документы.
- `.local-data/mail/` — локальная исходящая почта. Для сброса пароля откройте
  последний JSON для нужного email и перейдите по `link`. Отправка через SMTP не подключена.
- `local/migrations/` — SQL-схема, бизнес-функции и RLS. Миграции применяются
  автоматически при старте с учётом журнала выполненных миграций.

Резервная копия: остановите API и скопируйте всю `.local-data/` вместе с корневым
`.env.local` в закрытое место. Восстановление: верните их при остановленном API.
Существующие облачные пользователи, файлы и заказы автоматически не переносились.
Удаление облачного проекта через панель провайдера не выполнялось.

## Проверки

```bash
pnpm -r typecheck
pnpm -r --if-present lint
node --test local/tests/*.test.mjs scripts/tests/*.test.mjs
pnpm --filter @cleaning-go/admin build
```

Проверяется применение всей схемы к пустой базе, запросы приложений, регистрация
ролей, вход, RLS, защита файлов, восстановление пароля, сохранение данных,
полный цикл заказа, серверная цена, рабочая смена, GPS и идемпотентные отзывы.
Ручной чек-лист: [docs/MANUAL_QA.md](docs/MANUAL_QA.md).

## Возможности и ограничения

Каталог, выбор компании или клинера, заказы, назначения, смены, геолокация,
отзывы, сообщества, реферальные коды, бонусы, отчёты и админ-панель сохранены.
Обновления поступают через опрос локального API раз в 3 секунды с проверкой RLS.

PGlite рассчитан на один процесс API и локальное использование. Для нескольких
серверов нужен отдельный PostgreSQL и серверная инфраструктура. Интернет-карты
по-прежнему зависят от внешнего картографического сервиса.
Банковские платежи, выплаты, push и SMS не подключены; карточный платёж остаётся
`pending`, пока провайдер не подтвердит оплату. Фоновая геолокация на физических
iOS/Android требует отдельной проверки разрешений и сборки приложения.

Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Отчёт о проверке: [docs/LOCAL_MIGRATION_REPORT.md](docs/LOCAL_MIGRATION_REPORT.md).

## Безопасность

Веб-клиент использует `/api/local/*`: токен хранится в `HttpOnly` cookie и не
передаётся клиентскому JavaScript. Приватные фото также открываются через этот
серверный маршрут. Native-приложение сохраняет токен в SecureStore.

Обычный запуск веба и API слушает только `127.0.0.1`. Для телефона в своей сети
используйте явный `mobile:local`. После миграции безопасности нужно войти заново.
Администратор и его пароль остаются в локальном `.env.local`.

Проверка веб-ролей и защиты на отдельной временной базе после сборки:

```bash
pnpm --filter @cleaning-go/admin build
pnpm test:web
```

[Отчёт по безопасности и границы проверки](docs/SECURITY_AUDIT_2026-11-11.md).
Публикация в интернет требует HTTPS, настроенного reverse proxy, общего
ограничителя запросов и резервных копий. `TRUST_PROXY_HEADERS=true` допустим
только когда прокси перезаписывает входящий `X-Forwarded-For` и сервер нельзя
обойти прямым подключением.


Толық пайдаланушы сценарийін бөлек уақытша базада тексеру (алдымен вебті build жасаңыз):

```bash
pnpm test:functional
```
