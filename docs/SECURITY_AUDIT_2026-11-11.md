# Усиление безопасности Cleaning Go — 11 ноября 2026

Проверена локальная версия на основе GitHub `b0585ef`. Изменения сохранены в
рабочей копии; публикация и push не выполнялись. Отчёт не является гарантией
невозможности взлома или независимым внешним пентестом.

## Что исправлено

- Next.js и eslint-config-next обновлены с 15.5.21 до 15.5.28. Обновлены
  уязвимые прямые и транзитивные библиотеки, Zod и инструменты тестирования.
  Основание для обновления Next.js: [официальное уведомление от 14 октября](https://nextjs.org/blog/nextjs-security-update-october-14-2026).
- Веб работает через серверный `/api/local/*`. Cookie сессии — HttpOnly,
  SameSite=Lax; Secure включается для HTTPS. Bearer/refresh-токены не выдаются
  браузерному JavaScript. Удалена установка сессии из URL hash. Серверный
  service key никогда не пересылается из браузерных заголовков в API.
- CSP с индивидуальным nonce разрешает штатные скрипты Next.js; запрещены
  object, посторонние скрипты, фреймы и подмена base URL. Добавлены ограничения
  заголовков, no-referrer для защиты ссылок восстановления, отключены
  X-Powered-By и публичные browser sourcemaps.
- JSON читается потоком с ограничением размера, включая запросы без
  Content-Length. Для API — 64 KiB, для загрузок — до 16 MiB и более строгий
  лимит соответствующего bucket. Запросы, которые не являются JSON-объектами,
  отвергаются. Проверяется Content-Type.
- Ограничены размеры запросов к данным: число фильтров, полей, записей,
  вложенность отношений, IN-списки и результаты. Идентификаторы проверяются;
  значения передаются SQL-параметрами.
- Ограничители запросов не могут бесконечно разрастаться от случайных ключей.
  Произвольный X-Forwarded-For больше не позволяет обходить веб-лимиты по
  умолчанию. Лимиты неудачного входа разделены по аккаунтам.
- Хеширование паролей выполняется асинхронно с ограничением параллельных задач.
  Для отсутствующего пользователя также проверяется фиктивный хеш. HTTP-сервер
  ограничивает ожидание заголовков/запроса и размер заголовков.
- Для обычной смены пароля нужен текущий пароль. Сессия восстановления живёт
  15 минут и разрешает только завершение восстановления, проверку текущего
  пользователя и выход. Изменение пароля отзывает старые сессии и recovery-токены;
  новая ссылка отзывает предыдущую. Просроченные сессии очищаются при входе.
- Убрано чтение всех активных клиентов любым аккаунтом. В каталоге исполнителей
  доступны имена, но личные email, телефоны, коды приглашения и согласия скрыты
  от пользователей без соответствующих отношений. View использует
  security_invoker и базовые RLS-политики.
- Нельзя снять закрепление клиента за компанией прямым UPDATE либо удалением
  и повторным INSERT client_profiles. Защищены личные контакты аккаунта, рейтинг,
  число отзывов, владелец и код компании. Пользователь не меняет текст системного
  уведомления при отметке прочтения.
- Документ нельзя вставить сразу одобренным или от чужой компании: он должен
  ссылаться на реально загруженный собственный файл. Сообщения споров не могут
  подделывать внутреннюю заметку администратора.
- Файлы проверяются по сигнатуре PNG/JPEG/WebP/PDF и разрешённому MIME, а не только
  заголовку клиента. Сохраняются проверки владельца, пути, размера и RLS.
  Подписанные ссылки проверяют срок, формат подписи и целостность параметров.
  Файлы получают sandbox CSP, PDF выдаётся как attachment. Приватные веб-фото
  проходят через same-origin серверный маршрут.
- Изменение этапа заказа компании проверяет активную смену, назначение и
  собственные реально загруженные фотоотчёты в одной транзакции. Прямой RPC
  не обходит требование фото. История/уведомления и изменение статуса атомарны.
  Мобильный клиент тоже использует эту операцию и предлагает фото перед завершением.
- Изменение числа исполнителей опубликованного заказа блокирует строку заказа
  и проверяет уже занятые места. Отмена через веб использует общую бизнес-функцию.
- Внутренние SECURITY DEFINER-функции не доступны через RPC; для PUBLIC/anon
  отозваны права выполнения. У authenticated отозван доступ к storage.buckets.
- Веб и API по умолчанию слушают только loopback. Локальная папка данных — 0700,
  файлы окружения — 0600. Обновление отзывает старые browser sessions, чтобы
  требовался новый вход с HttpOnly cookie.

## Проверки и результаты

| Проверка | Результат |
|---|---|
| Node-интеграционные тесты и негативные проверки | 15/15 |
| Validation-тесты | 9/9 |
| Изолированные HTTP-проверки веба | 114/114 |
| TypeScript всех пакетов, веба и mobile | успешно |
| ESLint веба и mobile | успешно |
| Next.js production build | успешно |
| Android Hermes bundle через Expo export | успешно |
| Проверка браузерных assets на локальные серверные секреты | 61 файл, совпадений нет |

HTTP-проверки используют временную базу и отдельный веб-порт: они проверяют
страницы администратора, компании, клиента и клинера с активной сменой;
регистрацию трёх публичных ролей и запрет admin-регистрации; вход, выход,
серверный отзыв сессии, HttpOnly, отсутствие bearer-токена в JSON, соответствие
CSP nonce скриптам, CSRF, malformed JSON, загрузку/подписанный файл, создание и
отмену заказа. Тестовые аккаунты не остаются в основной базе.

Интеграционные проверки охватывают миграции, авторизацию, RLS, чужие адреса и
файлы, блокировки пользователей, сохранение данных, смены и GPS, согласование
цены, исполнителей, завершение заказа, наличную оплату и pending-карту,
идемпотентность отзывов, бонусы и возврат, восстановление пароля; отдельно —
подмену роли/контактов/рейтинга/баланса, обход company lock, SQL injection,
поддельные документы, MIME, path traversal и приватность каталога.

## Результат аудита зависимостей

До обновлений pnpm audit сообщал: 6 critical, 61 high, 44 moderate и 12 low.
После: **0 critical, 0 high, 0 moderate, 1 low**.

Единственное оставшееся предупреждение — `deepmerge@4.3.1` в Expo config:
[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4).
Готового upstream-исправления audit не предлагает. В репозитории сохранён
воспроизводимый pnpm-патч, исключающий __proto__, constructor и prototype при
обходе обоих операндов, включая вложенные объекты. Отдельный тест проверяет
воспроизведение атаки и исправление. Scanner продолжает видеть исходный номер
версии; предупреждение не скрыто и не исключено из audit.

Для совместимости Metro 0.82.5 с исправленной image-size 2.0.3 сохранён второй
маленький pnpm-патч: используется именованный imageSize и Buffer вместо имени
файла. Android bundle проверен после применения обоих патчей. Lockfile хранит
их хеши; при установке применяются файлы из `patches/`.

## Воспроизведение

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm test
corepack pnpm -r typecheck
corepack pnpm -r --if-present lint
corepack pnpm --filter @cleaning-go/admin build
corepack pnpm test:web
corepack pnpm --filter @cleaning-go/mobile exec expo export --platform android --output-dir dist-android
corepack pnpm audit
```

Последняя команда возвращает ненулевой код из-за указанного low предупреждения.
Веб-проверка требует свободный 127.0.0.1:3107. Основная база ей не используется.

## Границы и публикация

Полная визуальная проверка и клики по всем веб-формам не завершены: встроенный
browser host недоступен, управление обычным Chrome прерывалось изменением
пользовательского состояния. HTTP-проверка не заменяет проверку взаимодействия
в реальном браузере. Камера, файловый picker и фоновая геолокация на физическом
телефоне не проверялись; экспорт Android не является APK/device-тестом.

Реальные банковские платежи, SMS, SMTP и push не подключались. Антивирусная
проверка файлов, MFA администратора и распределённая защита от DDoS не добавлены.

Для интернет-развёртывания нужны HTTPS, закрытый backend-порт, reverse proxy,
внешние лимиты соединений/размеров/частоты и общий limiter для нескольких
процессов, резервные копии и мониторинг. PUBLIC_APP_URL должен содержать
реальный HTTPS origin. TRUST_PROXY_HEADERS=true допустим только за доверенным
прокси, который перезаписывает X-Forwarded-For; без него действует общий
консервативный локальный лимит. PGlite рассчитан на один локальный API-процесс.
Домен, сертификат, публичный сервер и внешняя инфраструктура в этой задаче
не настраивались.
