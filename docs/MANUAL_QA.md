# Ручная проверка MVP

## Подготовка

1. Выполните `node local/setup.mjs`, создайте администратора и запустите локальный API и веб-приложение по README.
2. Зарегистрируйте клиента и компанию через сайт. Администратор создаёт сообщество; клинер регистрируется по коду сообщества. Одобрите компанию и клинера в админ-панели.
3. Для cleaner выставьте `approved`, для admin доверенно задайте роль `admin`.
4. Заполните `.env` в корне либо соответствующие `.env.local` приложений.

## Главный сценарий

1. Клиент A копирует код на вкладке «Рефералы».
2. Клиент B регистрируется с этим кодом и создаёт заказ.
3. Одобренный клинер видит заказ и принимает его; повторное принятие другим
   исполнителем должно вернуть ошибку.
4. Клинер последовательно запускает маршрут, отмечает прибытие, начало и завершение.
5. На устройстве клиента в активном заказе появляется последняя координата.
6. Клиент подтверждает завершение и оставляет оценку.
7. В кошельке клиента A появляется 5%, а повторное завершение/повторный RPC не
   создаёт вторую награду.
8. Администратор видит заказ, оборот и награду.

## Негативные проверки

- Неподтверждённый клинер не принимает заказ.
- Клиент не меняет статус на `in_progress`.
- Клинер не видит чужую геопозицию и финансы.
- Геолокация не принимается до `on_the_way` и после конечного статуса.
- Отзыв нельзя оставить для незавершённого или чужого заказа.
- Обычный пользователь не меняет роль, комиссию или статус проверки.
- Повторное использование реферального кода не меняет пригласившего.

## Ограничения MVP

- Карточная оплата, SMS-провайдер и Expo Push требуют внешних учётных данных и не
  включаются автоматически.
- На экране маршрута показана актуальная координата; полноценная линия маршрута и
  навигация включаются после выбора и настройки картографического провайдера.
- Документы сохраняются в приватном Storage, но OCR/автопроверки нет.
- Подписки компаний представлены состояниями и настройками без списания денег.
