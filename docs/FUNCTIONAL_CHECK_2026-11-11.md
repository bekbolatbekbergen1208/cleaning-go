Кейінгі кеңейтілген нәтиже: [69 сценарий және тұрақтылық түзетулері](RELIABILITY_FIXES_2026-11-11.md).

Нәтиже: **66 функционалдық тексеріс, 114 веб/қауіпсіздік тексерісі және
24 автоматты тест өтті.** Вебтің production build және ESLint тексерісі өтті.
Түзетулер localhost:3000 сайтында қолданылды.

## Қалай тексерілді

Бөлек уақытша база мен 127.0.0.1:3108 веб-сервер қолданылды. Тек алғашқы
әкімші техникалық түрде дайындалды; қалған 5 аккаунт `/api/register` арқылы,
сайттың нақты тіркелу формасы жіберетін деректермен ашылды:

- 1 компания;
- 1 клинер;
- 3 клиент: шақыру коды жоқ, рефералмен келген және тікелей клинер таңдайтын клиент.

Әкімшінің мақұлдауы, қауымдастық құру, компанияның қосылуы, баға ұсыну,
клиенттің келісімі, клинердің тапсырыс қабылдауы мен кезеңдері, аяқталуын
растау, тоқтату және пікірді модерациялау — сервер көрсеткен HTML формаларынан
алынған нақты Server Action өрістерімен орындалды. Фото жүктеу, тапсырыс жасау,
GPS, пікір және парольді қалпына келтіру сайт қолданатын HTTP/API маршруттары
арқылы тексерілді. Нәтижелер базада қайта оқылып тексерілді.

Бұл браузердегі батырмаларды тінтуірмен басу сынағы емес: JavaScript оқиғалары,
файл таңдау терезесі және визуалды көрініс бұл сценарийде тексерілмеді.

## Төрт тапсырыс

| Сценарий | Нәтиже |
|---|---|
| Компанияға қолма-қол төлеммен тапсырыс | Фото/мекенжай сақталды; компания кабинетінде көрінді; баға ұсынылып, клиент растады; бонус бір рет шегерілді; клинер қабылдады; GPS клиентке жетті; фотоотчётпен аяқталды; клиент растады; қаржы есептелді |
| Тапсырысты клиенттің тоқтатуы | Нақты веб-форма арқылы cancelled күйіне өтті |
| Клинерді тікелей таңдау | Компанияға бекітілмеген клиент таңдады; клинер веб-формамен қабылдап, барлық кезеңді өтті; клиент аяқталуын растады |
| Карта арқылы төлем | Тапсырыс аяқталды, бірақ провайдер қосылмағандықтан төлем pending болып қалды; жалған paid/қаржылық финализация болған жоқ |

Қосымша: рефералмен тіркелу, компанияға бекіту, бастапқы/реферал бонусы,
клинер ауысымы, басқа рөлдің клинер орнын ала алмауы, жеке фотоотчёт,
пікірді қайталап жібергенде дубликат болмауы, рейтингтің жаңаруы,
пікірді жасыру/қалпына келтіру, есептер мен әкімшіде тапсырыстың көрінуі,
даудың әкімшіге жетуі, ауысым/тапсырыс біткенде GPS тоқтауы,
парольді қалпына келтіру және ескі сессияның жабылуы тексерілді.

## Табылған және түзетілген екі қате

1. **Бос шақыру коды тіркелуге кедергі болды.** Сайт формасы
   `referral_code: ""` жібереді, ал тексеріс оны жарамсыз код деп қабылдаған.
   Енді клиент пен компания үшін бос немесе тек бос орыннан тұратын код
   қалыпты өңделеді. Клинер үшін код міндетті; берілген бос емес кодтың
   форматы бұрынғыдай тексеріледі. Бұл сценарий регрессиялық тестке енгізілді.
2. **Жасырылған пікір рейтингте қала берді.** Пікірді жасыру немесе қалпына
   келтіру кезінде клинер/компания рейтингі мен пікір саны қайта есептелмеген.
   Жаңа транзакциялық DB trigger қосылды; бұрынғы қате рейтингтер де қайта
   есептеледі. Жасыруда рейтинг 0/пікір саны 0, қалпына келтіруде 5/1 болатыны
   нақты веб-форма мен автоматты тест арқылы тексерілді.

Компания коды арқылы бекітілген клиенттің тапсырысы өзінің компаниясына
жіберіледі — бұл бар бизнес ережесі. Тікелей клинер сценарийі компанияға
бекітілмеген бөлек клиентпен тексерілді.

## Қайта іске қосу

```bash
corepack pnpm --filter @cleaning-go/admin build
corepack pnpm test:functional
corepack pnpm test:web
corepack pnpm test
```

Толық 66 қадамның тізімі: [JSON нәтижесі](FUNCTIONAL_CHECK_2026-11-11.json).
Тест аккаунттары мен төрт тапсырыс уақытша базамен бірге тазартылды;
негізгі базаға сынақ аккаунттары қосылмады. JSON ішіндегі тапсырыс нөмірлері
жергілікті негізгі сайтта ашылатын тапсырыстар емес.

Нақты банк төлемі, SMS/SMTP/push жеткізуі және физикалық телефондағы камера/GPS
бұл тексеріске кірген жоқ. Карта төлемінің pending болуы осы шектеуге сәйкес.
