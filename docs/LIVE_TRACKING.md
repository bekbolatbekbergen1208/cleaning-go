# Карта и GPS для заказов в Астане

## Включение

1. В Supabase SQL Editor проекта выполните **только новую** миграцию
   `supabase/migrations/202610080029_multi_cleaner_live_tracking.sql`.
   Она сохраняет существующие точки, добавляет отдельную точку для каждого клинера,
   разрешает GPS с момента назначения (`accepted`) и прекращает отслеживание после работы.
2. Запустите веб-приложение: `corepack pnpm dev:admin`.
3. Для нового заказа в Астане клиент отмечает дом на карте. Для старого заказа
   клиент открывает «Карта и местоположение клинеров» и сохраняет точку адреса.
4. После «Взять заказ» клинер попадает на карту и нажимает «Включить геолокацию».
   Браузер запрашивает разрешение. Клиент и владелец компании открывают карту
   из своего заказа и видят всех назначенных клинеров.

## Поведение

- URL: `/order/<uuid>/tracking`; сервер проверяет участника заказа.
- GPS: `watchPosition`, отправка примерно раз в 10 секунд; время фиксирует сервер.
- Получение: Supabase Realtime, плюс повторный запрос раз в 10 секунд и при возврате во вкладку.
- Каждому клинеру соответствует своя запись `(order_id, cleaner_id)`.
- Через 2 минуты без GPS точка серая и отмечена как последняя известная;
  старое положение не показывается как актуальное, маршрут скрывается.
- Маршрут по дорогам для выбранного клинера пересчитывается раз в 45 секунд.
  Расстояние и время приблизительные, без данных о пробках.
- GPS доступен только участникам активного заказа. Членство в том же сообществе
  само по себе не даёт доступ к карте. После окончания уборки, отмены или спора
  точки удаляются триггером, даже если статус обновлён серверным действием.
- Кнопка остановки выключает GPS; последняя точка остаётся до окончания заказа
  и через 2 минуты отмечается как устаревшая.

## Ограничения браузера и сервисов

Для телефона требуется HTTPS. `localhost` поддерживается для проверки на компьютере.
Вкладка клинера должна оставаться открытой; закрытие, фоновые ограничения ОС и
блокировка телефона могут остановить GPS. Это не фоновый трекер мобильного приложения.
Если карта или маршрутизация недоступны, показывается ошибка, фиктивных точек и
прямой линии вместо дороги нет.

Карта: Leaflet 1.9.4 + тайлы OpenStreetMap с атрибуцией. Маршруты: публичный OSRM
для начального запуска. Для рабочего трафика настройте собственного/коммерческого
провайдера: публичные сервисы не дают SLA.

Дополнительные переменные (не обязательны для локальной проверки):

```env
NEXT_PUBLIC_MAP_TILE_URL=https://tile.openstreetmap.org/{z}/{x}/{y}.png
OSRM_BASE_URL=https://router.project-osrm.org
```

Политики и API:
- https://operations.osmfoundation.org/policies/tiles/
- https://project-osrm.org/docs/v5.24.0/api/
- https://leafletjs.com/reference-1.9.4.html

## Проверки

`corepack pnpm test:tracking` проверяет миграцию в изолированном PostgreSQL:
несколько клинеров, запрет чужих/заблокированных аккаунтов, диапазон координат,
чтение клиентом и компанией, очистка после завершения/отмены, повторное применение SQL.

Проверка на устройствах после миграции: открыть один заказ под клиентом,
владельцем компании и двумя назначенными клинерами. Разрешить GPS у клинеров;
убедиться в двух точках, обновлениях и маршруте; остановить GPS для проверки
устаревания, завершить заказ и убедиться в исчезновении точек.
